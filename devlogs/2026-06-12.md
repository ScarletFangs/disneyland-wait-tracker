# Devlog — 2026-06-12

## Project

Disneyland Wait Tracker — Building the read-only dashboard with live wait times

## Progress

- Built the dashboard screen that fetches live ride data when it opens, with a loading spinner while the request runs and an error state if it fails.
- Rides now show in a scrollable list with color coded wait times, pull to refresh, and the ThemeParks.wiki attribution at the bottom.
- Discovered that some theater shows report standby queues just like rides do, so filtering now combines a flag derived from the api with a hand curated "is ride" flag in the local land map.
- Wrote a dart extension that maps each ride to its wait color so the model stays free of any UI code.
- Worked through a string of real bugs along the way: a null assertion crash, an enum compared against a string that could never match, a silent key typo that quietly disabled the filter, and an off by one in the list builder.

## Reflection

This session was supposed to stop at grey boxes with real data but one thing led to another and I kept going. In my head that goal meant everything loads and works but nothing is refined, so pull to refresh, the filtering, and the color coding all went in now, in a working state but probably not the way I want them in the end. The filtering turned into a real design decision when I found out the api gives some theater shows a standby queue, so I split the idea into a flag the api gives me and a flag I curate myself in the json file. I think that holds up as a final design since disney does not change their offerings much within a decade, but rides and queue systems do shift over time, so I will need to revisit it. The bugs this session all came down to forgetting the different types. I am still not confident with the bang operator or the double question mark because I am not used to thinking about whether something can be null at one moment and have a value at another, and writing code around that. I also realized the react comparisons are not doing much for me since I have not written react in a long time, so I am mostly learning these concepts fresh, and it is better to treat them that way instead of leaning on a comparison I half remember.
