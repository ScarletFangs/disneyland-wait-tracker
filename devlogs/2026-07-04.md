# Devlog — 2026-07-04

## Project

Disneyland Wait Tracker — Finishing the sixth screen and the guest account upgrade

## Progress

- Built the Profile screen, the last of the six screens, with separate guest and signed in states, a proper logout button moved out of the placeholder, and the guest to account upgrade flow wired to the existing auth service method.
- Added two small getters to the auth service so screens can ask who is signed in and what their email is without touching firebase directly.
- Proved the upgrade flow end to end: favorites saved as a guest survive linking to a new email account and are still there after logging out and back in. The failure path shows an error and keeps the form usable for a retry.
- Fixed the lightning lane display on ride detail: the raw utc timestamp now formats as a local time, and rides without a price say the return time is included with multi pass instead of printing null.
- Recorded the current app state and marked it as v0.1, the first version with all six screens working.

## Reflection

Building the profile screen made me get precise about what guest mode actually is. I knew anonymous users still have a user id, but I was not sure what happens to that account when the user deletes the app, and that gap showed up in the first warning copy I wrote. The upgrade flow had a catch I did not expect. Linking a guest to an account keeps the same user id, so the auth stream never announces the change and the screen has to rebuild itself after a successful link. I already believed you could listen to a stream and still manually rebuild something, but this was my first time actually doing it in dart. The null check pattern came up again when I fixed the lightning lane time display, and I am finally getting the hang of recognizing when I need it. I just need to keep practicing until I can write it well on the first try. The dead end in the error path slipped in because I did not think that far ahead. I was focused on getting the screen working before figuring out the dead ends, so next time I want to check the failure paths against my own definition of done before I call a screen built.
