# Devlog — 2026-07-10

## Project

Disneyland Wait Tracker — Tracking down the unknown ride status and making errors user friendly

## Progress

- Traced the mystery "Unknown" status on Pirates of the Caribbean to a real api value, down, meaning the ride is temporarily unavailable, and added it as a proper status with its own on screen label.
- Moved all wait and status wording into one place on the ride model so the dashboard, favorites, and ride detail screens all say the same words, and adopted exhaustive switches so the compiler flags every screen that needs updating when a new status appears.
- Rewrote the auth service to translate firebase error codes into friendly sentences and return them instead of throwing, so screens just display whatever comes back. The real codes were confirmed by forcing each failure in the simulator instead of trusting the docs.
- Made failed data loads recoverable: the error message can now be pulled down to retry, which uncovered and fixed an old bug where a successful retry kept showing the stale error.

## Reflection

The unknown ride status changed how I write against this api. I should always keep a default for situations I never expected, and I should study the api more closely before writing instead of going off prior knowledge of what it can return. The error work turned into a decision about where things belong. I wanted the translation to live in the service because screens should mainly handle how to display information with widgets, while the service finds, supplies, and translates everything so future screens can use the same messages. Returning null to mean success was new to me but it felt natural once I used it from both sides. The retry bug showed me that the service can work again and the data can come back correctly while the screen state is still not set to actually display it, so walking through the code and tracking the different routes a screen can take matters. It is okay to make mistakes, but next time I want to look up the documentation that directly matches the error I printed in the console from actually testing it.
